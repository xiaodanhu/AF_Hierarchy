# STAGE 5 — Phrase-level zero-shot protocol on THUMOS14

## Concept

Standard ZSL-TAL holds out leaf ACTIONS. This protocol instead holds out entire
PHRASES (taxonomy families from `configs/thumos14_fam_map.json`, 9 phrases over
the 20 THUMOS actions). The model trains with fine-grained supervision and must
detect *novel phrases* at test time — categories for which not a single member
action was ever seen. This is a harder and cleaner compositional test than
leaf-holdout ZSL: nothing from the held-out family (neither the family text nor
any sibling action) appears in training.

**"Actions as attributes"** (arm B, ours): the seen ACTIONS serve as the fine
compositional vocabulary — the model is trained to align video features with
action-level text embeddings (11-sentence Qwen ensembles: class prompt + 10
temporal-phase descriptions). At test time the classifier weights are swapped
for PHRASE text embeddings (family prompt + 10 shared-phase sentences). The
hypothesis: training against many fine, phase-decomposed action descriptions
teaches a text-video alignment that transfers to a novel family described by
the same kind of phase language — the actions play the role that attributes
play in classic ZSL.

**Flat-phrase baseline** (arm A): identical pipeline, but training supervision
is collapsed to PHRASE granularity (all member actions of each seen phrase are
relabeled to the phrase name; 7 seen phrase classes). Same text ensemble
machinery, same test condition. The contrast isolates the value of fine
action-level supervision: A and B see the same videos, same segments (modulo
exact-duplicate merges), same test classes.

## Splits (EffPrompt-style multi-split)

5 splits, `n = 0..4`. Phrase inventory: 6 multi-member phrases
(`aquatic dive`, `ball throw`, `court jump strike`, `field throw`,
`implement strike`, `jump field`) + 3 singletons (`clean and jerk`,
`frisbee catch`, `soccer penalty`). Each split holds out 2 multi-member
phrases drawn by `np.random.RandomState(n).choice(multi, 2, replace=False)`
(sorted inventory; singletons are never held out — a singleton phrase is
indistinguishable from its action and would not test family-level transfer).

| split | held-out (unseen) phrases | seen actions | test GT segments |
|---|---|---|---|
| 0 | court jump strike, jump field | 15 | 608 + 676 |
| 1 | ball throw, court jump strike | 16 | 179 + 608 |
| 2 | ball throw, implement strike | 14 | 179 + 453 |
| 3 | field throw, jump field | 13 | 643 + 676 |
| 4 | implement strike, jump field | 13 | 453 + 676 |

Files (generated by `scripts/gen_phrase_splits.py`):
- `splits/train_phrase/THUMOS14/train/split_{n}.list` — seen ACTION names (arm B train vocab)
- `splits/train_phrase/THUMOS14/train_flat/split_{n}.list` — seen PHRASE names (arm A train vocab)
- `splits/train_phrase/THUMOS14/test/split_{n}.list` (+ identical `test_flat/`) — the 2 held-out PHRASE names

## Annotations and label filtering (verified mechanics)

`data/phrase_anno/thumos14_phrase_{n}.json` (arm B): copy of
`/data3/xiaodan8/thumos/annotations/thumos14.json` where, in TEST-subset
videos only, every GT segment whose action belongs to a held-out phrase is
relabeled with the PHRASE name. Seen-phrase segments in test videos keep
their action labels. This is safe because label selection is by NAME against
the split list in both places:
- dataset `libs/datasets/thumos14.py:137` — segments whose label is not in
  the split list are silently dropped;
- eval `libs/utils/metrics.py` `ANETdetection` builds its GT with
  `remove_subset_labels` against the same test list — seen-phrase action
  labels in test videos are excluded from eval GT, exactly like standard ZSL
  drops seen classes. Verified: eval GT rows = relabeled segment count
  (e.g. split 0: 1284 = 608 + 676) and `activity_index` is the identity.

`data/phrase_anno/thumos14_phraseflat_{n}.json` (arm A): same, plus
VALIDATION (train) videos relabeled action -> phrase wholesale. Held-out
phrase labels in train videos are then filtered out by the train_flat list.

Exact duplicates after relabeling (label, segment) are dropped — THUMOS
CliffDiving segments are duplicated as Diving with identical boundaries, and
both map to `aquatic dive`. Train-video segments of held-out phrases become
background in BOTH arms (dropped by the label map, video kept) — same
convention as the standard action-level ZSL splits in this repo; consistent
across arms, so the comparison is fair.

## External classification scores

`data/phrase_anno/thumos14_phrase_cls_scores.json`: `class` = the original 20
action names + the 9 phrase names (29 entries); each test-video score vector
is extended with phrase scores = max over member actions' scores.
`postprocess_results` maps prediction class names into this file by NAME
(`class_name_to_idx`), so one merged file serves both arms and all splits;
ordering only has to be internally consistent, which it is. Both arms use
this same `ext_score_file` — fusion is enabled and identical across arms.

## Text ensembles

- `configs/thumos14_phrase_ensemble.json` — hand-authored, 9 phrases x 11
  sentences: sentence 0 = `a video of a sports action: <phrase>, a family of
  related athletic movements`; sentences 1-10 describe the SHARED temporal
  structure of the family (distilled from the member actions' Qwen ensembles).
- `configs/thumos14_phrasemix_ensemble.json` — merge of the action ensemble
  (`thumos14_qwen_ensemble.json`) and the phrase ensemble: 29 keys x 11
  sentences; one file serves train (actions or phrases) and test (phrases).

## Metric

Novel-phrase mAP: mean AP over the 2 held-out phrases, tIoU 0.3:0.1:0.7
(THUMOS standard), averaged; best epoch per run (`max(mAP_list)` /
`tiou_mAP_list_best` in the log, epochs >= 5); report per split and the mean
over the 5 splits per arm.

## Arms

Both: `TIFAD_PROMPT_ENSEMBLE=configs/thumos14_phrasemix_ensemble.json
TIFAD_ATTR_ATTN=1 TIFAD_PROMPT_DROPOUT=0.3` (h19 s4 recipe), configs cloned
from `thumos14_i3d.yaml`, 16+5 epochs, ext-score fusion on.

- **A `flat-phrase`** — configs `thumos14_i3d_phraseflat_{n}.yaml`
  (subset template `.../{mode}_flat/...`, json `thumos14_phraseflat_{n}.json`).
  Trains on 7 seen phrase classes; zero-shot to 2 unseen phrases.
- **B `action-as-attributes` (ours)** — configs `thumos14_i3d_phrase_{n}.yaml`
  (subset template `.../{mode}/...`, json `thumos14_phrase_{n}.json`), plus
  `TIFAD_SEM_DEGRADE=0` (explicitly off: no parent-stem arithmetic for
  phrases). Trains on 13-16 seen action classes; zero-shot to 2 unseen
  phrases.

## Running

`bash run_stage5.sh` — 10 runs (2 arms x 5 splits) in 6 lanes: 3 per GPU on
GPUs 2 and 3 only (GPUs 0/1 are reserved). Resume-safe: a run's checkpoint dir
gets a `DONE` marker only after the log shows `All done!`; relaunching skips
DONE runs and redoes partial ones from scratch. Logs: `logs/s5_{A|B}_s{n}.log`;
checkpoints `ckpt/thumos14_i3d_phrase{flat}_{n}_s5{B|A}_{n}/`. The script
prints a per-split A-vs-B comparison table (and per-tIoU lists) at the end.
